## 3. 数据结构与职责

| 对象 | 保存什么 | 生命周期 |
| --- | --- | --- |
| SuccessfulTurn | raw_query、query、sql | 一条成功查询记录 |
| DataAgentState | 本轮原话、待查询问题、历史、改写结果和执行中间状态 | 单轮图执行 |
| ConversationMemoryStore | 按会话保存成功记录及当前话题起点 | 当前后端进程 |
| DataAgentContext | 数据库仓储、检索客户端等工具依赖 | 供本轮节点使用 |

State 的字段声明不会自动实现跨轮记忆。QueryService 负责读取历史和保存成功记录。

SuccessfulTurn 没有保存结果行，当前不能解析“刚才第一名”等结果引用。

## 4. 问题理解与意图路由

QueryRewriteResult 约定四种意图：

| 意图 | 后续动作 |
| --- | --- |
| follow_up | 使用补全后的问题继续查询 |
| new_topic | 使用独立问题查询，并切换历史起点 |
| clarify | 发送澄清消息，结束本轮 |
| out_of_scope | 发送范围提示，结束本轮 |

format_history 只把历史原话和完整问题转成 JSON，不把历史 SQL 放进改写提示词。

understand_query 通过“提示词 → 现有模型 → PydanticOutputParser”调用链返回结构化结果。

rewrite_query 图节点读取 raw_query 和 history，调用 understand_query，然后把 rewrite_result 与 query 写回 State。可查询意图的完整问题不能为空。

图入口改为：

```text
START → rewrite_query
          ├─ follow_up / new_topic → extract_keywords → 原有问数链路
          └─ clarify / out_of_scope → respond_query → END
```

respond_query 发送 message 类型事件，不调用模型、不执行 SQL。

解析器校验结构和意图枚举；节点对空查询和空回复补充检查，但不能保证模型理解正确，也没有完整的跨字段组合校验。

## 5. 会话编号与流式交互

请求体接收可选 session_id，路由交给 QueryService。

没有编号时，服务生成 UUID，并首先通过 session SSE 事件返回编号。前端用 useRef 保存，在后续请求体中提交。

前端增加 session 和 message 事件类型，分别处理会话编号与澄清、范围提示。

“新会话”和“清空”都会清除前端会话编号。旧后端历史不会因此删除，页面刷新后也不会恢复此前编号。

QueryService 同时消费：
- custom：节点发送的进度、结果和回复，包装成 SSE。
- values：图的状态快照，用于读取意图和最终状态。

## 6. 成功保存与话题边界

### 成功记录

run_sql 执行成功后返回 query_succeeded=True。

QueryService 正常消费完图输出，且最终状态具有成功标记时，创建 SuccessfulTurn 并追加历史。

执行异常、没有成功标记、仅回复澄清或范围提示时，不追加成功记录。执行成功不代表 SQL 语义正确。

### 识别到新话题

记忆容器保存：
- _histories：该会话全部成功记录。
- _topic_starts：当前话题在成功记录列表中的起点。

get_history 返回起点之后的列表切片，同时保留列表副本行为。

服务层一旦收到 new_topic，就调用 start_new_topic，把起点设为现有成功记录数，而不等待 SQL 成功。

因此新话题后续查询失败时，旧记录仍保留，但下一轮不会自动把它们作为当前话题历史。

new_topic_started 是单轮局部标记，防止连续状态快照重复触发切换。

### 没有收到改写结果

understanding_completed 表示服务层是否收到非空 rewrite_result，不表示语义正确或 SQL 成功。

这段请求处理退出时，如果始终没有收到结果，finally 调用 start_new_topic，保守隔开旧历史。

这一策略可能牺牲同话题失败后的连续追问便利，需要用户补全条件。断连、取消和同会话并发行为未专项验证。

## 8. 当前边界与阶段结论

第一阶段核心组件与前后端接线已完成，指定正常多轮场景由用户反馈通过；服务层失败处理由模拟验证覆盖，可以进行阶段收尾。

当前限制：
- 进程内存储，重启丢失，无容量控制或多进程共享。
- 同会话并发请求未串行化，不能保证并发下的历史顺序与话题边界。
- 会话编号不是身份认证或权限控制。
- SQL 成功标记不验证查询语义。
- 前端类型声明不等于网络 JSON 的运行时校验。
- 未验证断连、取消以及真实模型或数据库故障下的完整接口。
- 不保存查询结果，不支持历史结果引用。

第二阶段暂不开展。
